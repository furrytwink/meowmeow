# roblox-modular

A clean, modular, verifiable, zip-ready rebuild of the monolithic VisualsUI
executor script (`input/message(47).txt`, 3,121,224 bytes).

The original paste is a single Luau chunk containing four long-bracket string
payloads plus ~890 KB of top-level bootstrap driver code. This project splits
it into byte-exact modules, adds a module system with a tiny `require` shim,
and rebuilds a self-contained `dist/main.lua` whose runtime behavior is
identical to the original.

## Input anatomy (discovered during extraction)

```
local SOURCE, LIBRARY_SOURCE = [===[ ... ]===], [===[ ... ]===];   -- line 1
local BOOT_DATA = [===[ ...JSON... ]===];
local SKIN_SOURCE = [===[ ... ]===];                               -- 4th payload (not in the original spec!)
<~890 KB of top-level bootstrap driver code, ends with `return Visuals;`>
```

| Payload | Size | Consumed by the driver as |
|---|---:|---|
| `SOURCE` | 35,948 chars | `loadstring(SOURCE, "@adapter")` → chunk receives `(LIBRARY_SOURCE, Remote)` → returns NeverLose |
| `LIBRARY_SOURCE` | 323,613 chars | passed into the adapter chunk, which `loadstring`s it as `"@visualsui"` |
| `BOOT_DATA` | 1,827,778 chars | `HttpService:JSONDecode(BOOT_DATA)` → `Remote.manifest` + embedded text/binary assets |
| `SKIN_SOURCE` | 28,664 chars | `loadstring(SKIN_SOURCE, "@skins")` → `mount(host)` (MM2-gated) |

All four are **strings at runtime**, so the module system serves them as
source-string modules and the driver behavior is unchanged.

## Module system

Two module kinds live behind the bundled `require` shim:

1. **Source-string modules** — `require("neverlose")`, `require("visualsui")`,
   `require("assets")`, `require("neverlose.skins")` return the *exact strings*
   the original monolith held in its long-bracket literals. The driver then
   `loadstring`s / JSON-decodes them exactly as before.
2. **Code modules** — every file under `src/modules/` is discovered by the
   bundler and exposed as `require("modules.<name>")`. Factories run once and
   are cached (nil-safe). `require("modules")` returns the index table.

### Extracted feature modules

The driver buries whole features inside `guard("name", fn)` blocks that close
over driver locals. **All 39 top-level `guard()` blocks** are extracted into
`src/modules/` as **ctx-injected feature modules**: the block body stays
byte-frozen original code, wrapped as `return function(ctx) ... end`, and the
driver re-enters it with the exact locals it used to close over:

```
guard("aimbot", function()
        return require("modules.aimbot")({
                ESP = ESP, LocalPlayer = LocalPlayer, NeverLose = NeverLose,
                Notification = Notification, Players = Players, RunService = RunService,
                Sections = Sections, onUnload = onUnload,
        });
end);
```

**Live getters for the mutable `ALIVE` flag.** 25 blocks read the driver's
`ALIVE` flag (`local ALIVE = true`; `Unload()` flips it to `false`). A ctx
*value* copy would freeze it `true` and change unload behavior, so those blocks
receive a **live getter** instead of a value, and their free reads of `ALIVE`
are rewritten to getter calls:

```
guard("lighting", function()
        return require("modules.lighting")({
                ESP = ESP, NeverLose = NeverLose, Sections = Sections,
                __ALIVE = function() return ALIVE end,   -- live, not a snapshot
        });
end);
-- inside the module:  while __ALIVE() do ...  -- returns the CURRENT driver value
```

The rewrite is mechanical and proven on every build: a scope-aware Lua parser
(`scripts/luascopes.py`) resolves every identifier through the block's lexical
scopes, so only true upvalue reads are rewritten — strings, comments, field/
method names (`X.ALIVE`), table keys (`{ALIVE = ...}`) and shadowed locals are
never touched. `make verify` re-proves, for each of the 25 modules, that (a)
zero free reads of `ALIVE` remain and (b) replacing `__ALIVE()` back with
`ALIVE` reproduces the frozen driver slice byte-for-byte. Blocks must also
never *assign* to a driver-local upvalue or use `...` in callback scope — the
audit (`scripts/plan_feature_modules.py`) enforces this mechanically and
cross-checks the free-variable sets against `luau-analyze`;
`scripts/lualex.py` locates each block's balanced `end);` so slicing never
depends on what follows the block.

The `ctx`/`live` fields live in `FEATURE_MODULES` (scripts/extract.py). Feature
files are re-derived from the input on every `make extract` — hand-edits to
the frozen body are impossible by construction (hash-checked); to change
behavior, edit `input/message(47).txt` or add a new module instead.

Adding a module:

```
1. drop src/modules/mything.lua into place
2. make bundle            # regenerates src/modules/init.lua + dist/main.lua
3. require("modules.mything") from anywhere below the entrypoint
```

## Commands

```
make extract            # split input/message(47).txt -> src/ + assets/ + manifest
make bundle             # build dist/main.lua (also regenerates the module index)
make verify             # run ALL verification groups (writes scripts/verification_log.txt)
make zip                # build dist/roblox-modular.zip   (INCLUDE_INPUT=1 embeds input/)
make smoke              # lune runtime smoke test only
make all                # extract + bundle + verify + zip
make clean              # remove generated artifacts
```

Tools (optional but recommended): `luau`, `luau-analyze`, `luau-compile`,
`stylua`, `selene`, `lune`. The Makefile auto-adds `../tools` to `PATH` if
present; `verify.py` also searches `tools/` next to the project. Missing tools
are reported and only their check is skipped.

## Verification coverage (make verify)

1. **Extraction integrity** — the input is re-parsed from scratch and every
   payload/driver SHA256 is compared against `scripts/extract_manifest.json`;
   the split files must round-trip byte-exactly; `src/init.lua` must embed the
   driver after the marker line with exactly the documented feature-module
   patches applied, and every derived feature module must be a byte-exact
   re-derivation of its original block.
2. **BOOT_DATA integrity** — JSON parses; `manifest.count == len(files)`;
   `manifest.total == sum(sizes)`; every binary asset decodes at its declared
   size and re-encodes byte-exactly; text assets match and parse; skyboxes
   (64 names x 6 faces) are cross-checked against the file registry; a full
   reconstruction from `manifest.json + text/* + binary/*` is byte-identical
   to `boot_data.json`.
3. **Luau syntax/style** — `luau-compile --binary` (hard syntax) on every
   chunk incl. `dist/main.lua`; `luau-analyze --mode=nonstrict` with
   environmental unknown-global notices filtered; `stylua --check` on the
   hand-written files; `selene` (executor std) over all of `src/`.
4. **Bundle integrity** — fresh `bundle.py` run; embedded payloads must hash
   equal the extraction manifest; every `require("...")` literal resolves; no
   duplicate module ids; no missing assets; `dist/main.lua` compiles.
5. **Runtime smoke test** — `lune` runs `dist/main.lua` under a stubbed
   Roblox/executor environment (in-memory FS, HttpService with real JSON
   decode, permissive instances/services, real task scheduler). Asserts: the
   driver chunk runs to completion, the SOURCE payload really compiles
   (`luau.load`) and matches the extracted file, and the driver's Remote
   bootstrap JSON-decodes BOOT_DATA **byte-exactly**. See note below.
6. **Zip integrity** — fresh `build_zip.py`; CRC test; required members
   (`src/`, `assets/`, `scripts/`, `dist/main.lua`, `README.md`, `Makefile`);
   no absolute paths or `..` segments; `input/` excluded unless
   `INCLUDE_INPUT=1`.

### Verification scope notes

* `stylua --check` is intentionally scoped to the hand-written files
  (`src/assets/init.lua`, `src/modules/*.lua`). The extracted payloads and the
  driver must stay byte-exact (enforced by hash checks), so re-formatting them
  is forbidden by design.
* `luau-analyze` has no Roblox definitions file mechanism in this build, so
  "Unknown global/type" notices for executor APIs are filtered; any *other*
  finding fails the check. `selene` runs unfiltered (0 errors) thanks to
  `executor.yml`, which declares the executor surface (`getgenv`, `readfile`,
  `syn`, `crypt`, LPH_* obfuscation attributes, ...).
* The luau smoke test observes that the driver JSON-decodes BOOT_DATA
  byte-exactly, but it cannot drive a real UI. Manual executor test: execute
  `dist/main.lua` in a Roblox executor; the overlay should mount, and
  re-executing should unload the previous instance (generation guard).

## Behavior preservation

* `src/init.lua` = a small require-prologue + the original driver tail
  (byte-exact apart from the documented feature-module patches, marked by a
  comment). The original top-level execution order, local names, globals
  (`getgenv`, `GLOBAL.Visuals`, generation guard), and the final
  `return Visuals;` are untouched. Extracted features run at exactly the same
  point in the bootstrap with the same values (now passed via ctx instead of
  lexical closure). The 25 blocks that read the mutable `ALIVE` flag get it
  through a live getter (`__ALIVE = function() return ALIVE end`) and read it
  via `__ALIVE()`, so post-unload behavior (every loop/condition that must
  stop when `Unload()` flips the flag) is identical to the original closure —
  re-proven per module by `make verify` (0 remaining free reads; the rewrite
  reverse-maps byte-exactly onto the frozen driver slice).
* Payloads are served as strings, so `loadstring`/`JSONDecode` semantics —
  including line-ending normalization Luau applies at compile time — are
  identical to the original monolith.
* The bundler embeds assets/boot_data.json verbatim; no re-serialization.
* Data note (original property, preserved): `manifest.files` declares
  menusounds/manifest.json as 2289 bytes (embedded: 2204) and
  stickers/manifest.json as 2896 (embedded: 2750); fxatlas matches exactly.
  537 of the 555 manifest paths are not embedded in BOOT_DATA at all — the
  runtime fetches those over HTTP into its `Salad Visuals` cache.
